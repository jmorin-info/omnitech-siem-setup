# CONTRACT.md — SEAL → Graylog integration contract (single authority)

This document is AUTHORITATIVE for all layers (SQL → Logstash → Graylog →
detections). Column names verified against the SEAL QA database on 2026-07-10.
Every layer MUST comply with it. Frozen decisions (operator sign-off).

## D0. Decisions taken
- **Scope**: QA only (`bx-qa-seal-vm.omnitech.security` → `10.33.120.2:1433`, pinned IP, `hostNameInCertificate=<FQDN>`, `encrypt=true;trustServerCertificate=false`).
- **Streams / index sets** (repo convention):
  `OMNI - SEAL Accès` (`omni-seal-access`, 12-month retention),
  `OMNI - SEAL Alarmes` (`omni-seal-alarm`, 12 months),
  `OMNI - SEAL Audit` (`omni-seal-audit`, 24 months).
- **Time zone**: server UTC+2. `timestamp` = business time in **UTC**.
  EVENEMENTS/ALARMES: `<local_col> AT TIME ZONE 'Romance Standard Time' AT TIME ZONE 'UTC'`.
  Audit.*: use `OperationDateUtc` (already UTC).
- **Decoding**: lookup `REEV_CODE → REEV_LIBELLE` via `dbo.REF_EVENEMENT` (Graylog CSV Data Adapter regenerated by cron). `severity_num` = raw `EVEN_SEVERITE`; detections rely on the **decoded REEV_CODE**, not on the (unreliable) SEAL severity.
- **Identity**: `EVEN_PHYSICAL_NUMBER → milf.BADGES.PHYSICAL_NUMBER → MATRICULE`.
  `identity_upn` NOT resolved in SQL (absent in QA) → enriched on the SIEM side (matricule→AD, mirror rule). `AcApi.TAG` is used only to know whether a badge is **known** (EVT-002); it does not carry a matricule.
- **Graylog Open edition**: `[SEQ]` rules → approximated via pipeline state where feasible, otherwise v2, documented limitation. No native Correlation event definition, no native JDBC lookup.

## D1. GDPR minimization (columns FORBIDDEN in the SIEM view)
Never expose: `UTILISATEUR.UTI_PASSW`, `UTI_SEED`, `UTI_HASH_PASS`,
`UTILISATEUR_PASSWORD_HISTORY.*`, `DETAIL_FICHE.DFIC_VAL_PHOTO`.
`milf.BADGES`: expose ONLY `PHYSICAL_NUMBER`, `BADGE_NUMBER`, `MATRICULE`,
`STATUS`, `USER_TYPE`, `COMPANY`, `SITE`. **Exclude** PHOTO, LAST_NAME,
FIRST_NAME*, BIRTH_*, ADDRESS, CITY, ZIPCODE, NATIONALITY, SEX, MOTHER_*,
FATHER_*, MAIDEN_*, PERSONNAL_PHONE, QR_CODE* (PII, not needed).
Descriptions: prefer `*_ANON` (`EVEN_USER_DESCRIPTION_ANON`, `AL_USER_DESCRIPTION_ANON`).

## D3. Decodings (validated §9.2 RECON)
- LIFESTAGE: INF/BEG/END/ACK/NOP. LIFESTATUS: INF/LIV/END/ACK.
- REEV_CODE (via REF_EVENEMENT): SEM113=door forced open, SEM105=reported physical opening, SEM759=console login, SEM138/SEM280=user/secondary-reader access, SEM805=manual trigger, SEM73=UTL database modified, SEM70/71=UTL life lost/starting, SEM0=generic.
- Audit Operation: Connection/Deconnection/**ConnectionFailure**/SwitchProfile.
- OperationChannel: SEAL Light Wall / SEAL Exploitation / **SealAdmin** / SealMillefeuille.
- TagMovements.Status: VAL/PRE/ANN. **ANN→VAL = reactivation (ACC-004)**, VAL→ANN=deactivation, ∅→PRE=creation.

## D5. Logstash watermark (safe pattern)
`WHERE WatermarkBig > :sql_last_value AND WatermarkBig < CONVERT(BIGINT, MIN_ACTIVE_ROWVERSION()) ORDER BY WatermarkBig ASC`.
Views exposing `CONVERT(BIGINT, <rowversion>) AS WatermarkBig`:
`vw_SealEvents_SIEM` (EVEN_ROWVER), `vw_SealAlarms_SIEM` (VERSION),
`vw_SealAudit_SIEM` (RowVer, UNION ALL of the 15 tables — database-global rowversion
= 1 monotonic watermark). `vw_SealIdentity_SIEM`: no watermark (enrichment).
Initial seed: watermark at the current value (no historical backfill).
