System: bx-it-graylog-vm (Debian 13, Graylog 7.1.3, local OpenSearch 127.0.0.1:9200).

## A.8.15 — Logging

**Requirement.** Produce, protect and retain logs of activities, exceptions, faults and relevant events, with a defined retention.

### Available evidence

1. Active collection — 14 inputs running:

```bash
api_get '/system/inputstates' | jq -r '.states[] | [.message_input.title, .state] | @tsv'
```

Expected: 14 lines, all `RUNNING` (Beats TLS 5044, FortiAnalyzer 1514, ESET 1515, vSphere 1516, FortiManager 1517, FortiClient EMS TLS 1518, Linux 1519, Aruba 1520, GELF HTTP/UDP 12201). The encrypted transports (Beats TLS, Syslog TLS 1518) are visible in the titles.

2. Freshness and volume per source (real collection scope):

```bash
curl -s 'http://127.0.0.1:9200/omni-*,graylog_*/_search' -H 'Content-Type: application/json' \
  -d '{"size":0,"aggs":{"src":{"terms":{"field":"event_source","size":50},"aggs":{"last":{"max":{"field":"timestamp"}}}}}}' \
  | jq -r '.aggregations.src.buckets[] | [.key, .doc_count, .last.value_as_string] | @tsv'
```

Expected: ~40 `event_source` values, the main families with a most-recent event less than 35 minutes old (observed on 07/02: fortigate 56.4M, windows_security 21.8M, sysmon 21.7M, windows 6.4M, vsphere 3.9M, bunkerweb, m365, vaultwarden..., all fresh to under 30 min).

3. Retentions calibrated per index set (policy: `docs/POLITIQUE-RETENTION.md`):

```bash
api_get '/system/indices/index_sets?skip=0&limit=0' | jq -r \
  '.index_sets[] | [.title, .rotation_strategy.rotation_period // "-", .retention_strategy.max_number_of_indices] | @tsv'
```

Expected: P1D rotation everywhere; Windows Security / vSphere / ESET = 180 d, Microsoft 365 = 365 d, other sources = 90 d (provisioned by `41-retention-iso.sh`). Known discrepancies: Cert Orchestrator at 12 d (see gaps).

4. Network protection of collection — filtering by emitting source IP:

```bash
nft list ruleset | grep -c saddr        # expected: 25 rules filtered by source IP
nft list ruleset | grep 5044            # example: Winlogbeat restricted to 10.33.0.0/16
```

5. Reference documents: `docs/STD-JOURNALISATION.md`, `docs/POLITIQUE-RETENTION.md`, `docs/INVENTAIRE-SOURCES.md`.

### Gaps and minimal action

- Cert Orchestrator channel dead: the nftables rule `udp dport 12201` declared at `06-firewall.sh:67` is absent from the live ruleset (`nft list ruleset | grep 12201` empty) and `curl -s http://127.0.0.1:9200/omni-cert*/_count` = 0. Action: replay `06-firewall.sh` then verify document arrival in `omni-cert_0`. Caution: the `event_source=cert_parc` events present come from another source (BX-PKI2022 via Winlogbeat, rule `omni-winother-10-cert-parc` in `12-graylog-pipelines.sh`), which keeps the watchdog green and masks the orchestrator's silence.
- Inconsistent retentions: Cert Orchestrator 12 d (to be raised to 90 d minimum); ~70,000 `forti_dhcp` events stored in the `omni-m365_*` indices (365 d) for lack of a dedicated stream; Linux/Aruba authentication at 90 d versus 180 d for Windows Security. Action: CISO arbitration documented in `docs/POLITIQUE-RETENTION.md`.
- Declared sources with zero events (NPS, Entra, NinjaOne): enable them or document the temporary exclusion in `docs/INVENTAIRE-SOURCES.md`.
